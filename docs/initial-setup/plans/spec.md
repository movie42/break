# Break 초기 셋업 - 명세

이번 셋업의 결과물은 **규칙을 편집해서 저장하는 앱**이다. 차단은 실행되지 않는다. 아래 명세도 그 범위를 따르되, 규칙 파일 포맷과 스케줄 판정은 다음 작업의 데몬이 그대로 가져다 쓰므로 지금 확정한다.

## 화면/기능 흐름

- 앱 실행: 트레이 아이콘 등록 → 메인 창 표시
- 첫 실행, 규칙 파일 없음: 빈 규칙으로 시작하고 세 화면 모두 빈 상태로 렌더. 파일을 미리 만들어 두지 않는다
- 창 닫기 버튼: 창만 숨김 → 프로세스는 트레이에 남는다
- 트레이 "열기": 창 표시와 포커스 / 트레이 "종료": 프로세스 종료
- 사이트 추가: 도메인 입력 → 규칙 파일에 저장 → 목록에 표시
- 시간대 추가: 요일과 시작·종료 시각 입력 → 규칙 파일에 저장
- 앱 재실행: 저장했던 사이트와 시간대가 그대로 보인다
- 모든 화면 상단: 차단이 아직 실행되지 않는다는 안내를 아래 문구 그대로 표시한다

  > 아직 차단은 동작하지 않습니다.
  > 지금은 사이트와 시간대를 저장하는 것까지만 가능합니다.

## 상태 정의

| 상태 | 설명 |
| --- | --- |
| 규칙 없음 | 규칙 파일이 없거나 대상이 하나도 없음 |
| 대기 | 규칙은 있으나 현재 시각이 어느 차단 구간에도 속하지 않음 |
| 차단 구간 | 현재 시각이 차단 구간 안. **이번 셋업에서는 상태 표시만 하고 아무것도 차단하지 않는다** |
| 실행 불가 | 차단을 요청했으나 권한이 없음. `Enforcer`가 `NotPrivileged`를 반환한 경우로, 이번 셋업에서는 항상 이 상태다 |

## 규칙 파일 위치

지금은 사용자 권한으로 쓸 수 있는 위치를 쓰고, 다음 작업에서 root 데몬이 읽을 수 있는 시스템 위치로 옮긴다. 옮기는 일이 다음 작업의 첫 단계라 경로를 상수 한 곳에 모아둔다.

| | 이번 셋업 | 다음 작업 (데몬) |
| --- | --- | --- |
| macOS | `~/Library/Application Support/com.movie42.break/rules.json` | `/Library/Application Support/Break/rules.json` |
| Windows | `%APPDATA%\Break\rules.json` | `C:\ProgramData\Break\rules.json` |

## 스케줄 판정 규칙

`TimeWindow`는 시작 시각, 종료 시각, 요일 집합으로 표현한다.

- **시작 < 종료** (예: 09:00~18:00): 해당 요일의 그 구간만 차단
- **시작 > 종료** (예: 22:00~02:00): 자정을 넘는 구간이다. **시작 시각이 속한 요일을 기준으로** 판정한다. 월요일이 켜져 있으면 월 22:00부터 화 02:00까지가 차단 구간이고, 화요일이 꺼져 있어도 이 구간은 차단된다
- **시작 == 종료**: 24시간 차단으로 본다
- **경계**: 시작 시각은 포함하고 종료 시각은 제외한다 — `[시작, 종료)`
- 시각은 로컬 시간대로 판정한다. UTC로 변환하지 않는다

## 규칙 변경의 반영 시점

차단이 돌아가는 중에 목록을 고치는 상황은 흔하다. 저장 시점과 적용 시점이 벌어지면 "추가했는데 왜 안 막히지"가 되므로 지금 못박는다. 이번 셋업에서는 저장까지만 구현하고, 적용은 다음 작업에서 데몬이 이 규칙대로 한다.

- 규칙을 저장하면 즉시 적용된다. 앱 재시작이나 차단 구간이 바뀌기를 기다리지 않는다
- 차단 구간이 진행 중일 때 대상을 추가: 그 시점부터 차단 대상이다
- 차단 구간이 진행 중일 때 대상을 제거: 즉시 해제된다
- 판정은 저장된 규칙을 매번 다시 읽어서 한다. 시작 시점의 규칙을 메모리에 붙들고 있지 않는다

## 엣지 케이스

- 규칙 파일이 깨진 JSON: 빈 규칙으로 시작하되, 원본을 `rules.json.corrupt-{타임스탬프}`로 옮긴 뒤 진행한다. 조용히 덮어쓰지 않는다
- 같은 도메인을 두 번 추가: 중복 저장하지 않는다. 목록에 이미 있으면 무시한다
- 도메인 입력 형태가 제각각 (`https://x.com/path`, `www.x.com`, `x.com`): 저장 전에 호스트 부분만 남기도록 정규화한다. hosts 파일에 들어갈 수 있는 건 호스트명뿐이라 경로나 스킴이 붙으면 다음 작업에서 그대로 깨진다
- 여러 시간 구간이 겹침: 하나라도 차단 구간이면 차단으로 본다
- 시스템 시각이 뒤로 점프 (시간대 변경, 수동 조정, 절전 복귀): 매 판정마다 현재 시각을 다시 읽으므로 별도 처리가 없다. 경과 시간을 누적하는 방식은 쓰지 않는다
- `Enforcer`가 `NotPrivileged`를 반환: 이번 셋업에서는 오류가 아니라 정상 경로다. 화면에 안내로 표시하고 저장은 정상 진행한다

## 알려진 한계 — 다음 작업에서 확인할 것

`hosts` 파일 차단은 브라우저가 DNS-over-HTTPS를 쓰면 우회될 수 있다. 브라우저가 운영체제의 이름 해석을 거치지 않고 자체적으로 암호화된 DNS 서버에 직접 물어보는 방식이라, `hosts`에 적어둔 항목이 무시될 수 있다. 브라우저와 설정에 따라 동작이 갈리므로 추측하지 말고 다음 작업에서 Safari·Chrome·Firefox 각각으로 실제 확인한다. 뚫린다면 방화벽 규칙(macOS는 PF)으로 해당 IP와 알려진 DoH 서버를 함께 막는 작업을 별도로 잡는다.
