# 규칙 파일 v3 — 시간대 켜기/끄기

작성: 2026-09-03

## 왜 바꿨나

v2에서는 시간대를 만드는 순간 그게 곧 실행이었다. 잠시 쉬고 싶으면 시간대를 지우는 수밖에
없었고, 지우면 요일과 시각을 다시 입력해야 했다. 그래서 "만드는 것"과 "실행하는 것"을
분리했다.

## 달라진 모양

`TimeWindow`에 `enabled`가 붙었다.

```json
{
  "id": "w1",
  "start": { "hour": 22, "minute": 0 },
  "end": { "hour": 2, "minute": 0 },
  "days": ["monday"],
  "groupIds": ["g1"],
  "enabled": true
}
```

- `enabled`가 `false`인 시간대는 `window_contains`가 무조건 거짓을 돌려준다. 판정의 맨 앞
  줄이라 요일·시각 계산까지 가지 않는다
- 앱에서 새로 만든 시간대는 `false`로 저장된다. 목록의 토글을 켜야 실행된다
- 필드가 없는 파일은 `true`로 읽는다(`#[serde(default = "enabled_by_default")]`). v2까지
  만들어 둔 시간대는 전부 켜져 있던 것이므로 열자마자 하던 일을 그대로 이어간다

## 버전을 3으로 올린 이유

`enabled`는 필드 하나 추가라 옛 프로그램도 파일을 읽는 데는 문제가 없다. 문제는 **읽고 나서
하는 일**이다. v2 데몬은 `enabled`를 모르는 필드로 넘기고, 꺼 둔 시간대까지 켜진 것으로
보고 막는다 — 사용자가 껐는데 계속 막히고, 어디에도 그 사실이 보이지 않는다.

`store::load_from`은 파일의 `version`이 그 프로그램이 아는 버전보다 크면
`StoreError::UnsupportedVersion`으로 거절한다. 버전을 3으로 올리면 낡은 데몬은 파일을
거절하고 차단을 푼 뒤 로그를 남기며(`RulesUnreadable`), 앱은 "차단 프로그램이 앱보다
오래됐습니다" 배너를 띄운다. 조용히 잘못 막는 것보다 눈에 보이게 안 막는 쪽이 낫다.

`Rules::migrate`의 v1 → 그룹 접기 분기는 `version < 2` 조건으로 바뀌었다. 예전에는
`version < RULES_VERSION`이었는데, 그대로 두면 v2 파일에서 `default`라는 id의 그룹이
있을 때 그룹을 안 고른 시간대에 그 그룹이 멋대로 붙는다.

## 실행 중에는 풀 수 없다

차단 도구가 잠깐의 충동에 무너지면 쓸모가 없다. 그래서 지금 실행 중인 시간대에 대해서는
해제 방향의 조작을 전부 막았다. 판정은 화면에서 5초마다 다시 한다(`useNow`).

| 조작 | 실행 중 |
| --- | --- |
| 시간대 추가 | 가능 (꺼진 상태로 만들어진다) |
| 시간대 켜기 | 가능 |
| 실행 중인 시간대 끄기 / 지우기 | 막힘 |
| 실행 중이 아닌 시간대 끄기 / 지우기 | 가능 |
| 그룹에 주소 추가 | 가능 |
| 실행 중인 시간대가 쓰는 그룹 지우기 / 주소 빼기 | 막힘 |
| 그룹 이름 수정 | 가능 (막는 대상이 그대로라서) |
| 차단 프로그램 제거 | 막힘 |

화면에서 버튼을 지우는 것과 별개로 핸들러에서도 한 번 더 막는다. 5초 간격 판정과 클릭
사이에 시간대가 시작될 수 있기 때문이다.

## 언제 풀리는지 계산하기

배너에 "9월 4일 00:00에 풀립니다 / 남은 시간 5시간 43분"을 띄운다. 시간대 하나의 끝이
아니라 **켜 둔 시간대 전체를 합친 구간의 끝**이다. 22:00~02:00과 01:00~09:00이 나란히
켜져 있으면 09:00이 답이다.

`merge.ts`의 `mergedWeek`이 요일별 구간을 주(週) 단위 분 좌표(0~10080)로 펴서 합친다.
일요일 끝과 월요일 처음이 맞닿으면 하나로 잇는다. `active.ts`의 `currentSession`이 지금
분이 들어 있는 구간을 찾아 끝을 돌려준다. 일주일이 통째로 막히면 끝이 없으므로 `null`이고,
화면은 "풀리는 시각 없음"을 띄운다.
