# 규칙 파일 v2 — 사이트 그룹

작성: 2026-08-31

## 왜 바꿨나

v1에서는 `rules.json` 맨 위에 `sites` 하나만 있었다. 시간대가 몇 개든 차단 대상은 항상
그 목록 전체였다. "밤에는 소셜만, 낮에는 소셜과 쇼핑" 같은 걸 표현할 방법이 없었다.

v2는 사이트를 **그룹**으로 묶고, 시간대가 그룹을 지목한다. 어느 시각에 막히는 주소는
그때 켜져 있는 시간대들이 지목한 그룹의 합집합이다.

## 달라진 모양

```json
{
  "version": 2,
  "groups": [
    { "id": "g1", "name": "소셜", "sites": [{ "host": "youtube.com" }], "apps": [] }
  ],
  "schedule": {
    "windows": [
      {
        "id": "w1",
        "start": { "hour": 22, "minute": 0 },
        "end": { "hour": 2, "minute": 0 },
        "days": ["monday"],
        "groupIds": ["g1"]
      }
    ]
  }
}
```

- `sites` / `apps`가 최상위에서 사라지고 `groups[].sites` / `groups[].apps`로 들어갔다
- `TimeWindow`에 `groupIds`가 붙었다. 비어 있으면 그 시간대는 아무것도 막지 않는다

## 옛 파일을 여는 방법

`store::load_from`이 파일을 읽은 뒤 `Rules::migrate`를 부른다. v1 파일은 이렇게 접힌다:

1. 최상위 `sites` / `apps`를 `default`라는 id의 그룹 하나로 옮긴다 (이름 "차단 목록")
2. `version < 2`이면 `groupIds`가 빈 시간대에 `default`를 넣는다

그래서 업그레이드 직후 막히는 주소는 v1과 정확히 같다. `sites` / `apps` 필드는
비어 있으면 다시 쓰지 않으므로(`skip_serializing_if`), 다음 저장에서 자연히 사라진다.

`groupIds`가 비어 있어도 v2 파일에는 손대지 않는다. v2에서 그건 "그룹을 아직 안 고른
시간대"라는 뜻이지 옛 파일이 아니기 때문이다.

## 판정 함수 두 개

`schedule.rs`에 둘이 나란히 있고 답하는 질문이 다르다.

| 함수 | 묻는 것 | 쓰는 곳 |
| --- | --- | --- |
| `is_blocking_at` | 지금 켜져 있는 시간대가 있나 | 앱 상태(`blockingNow`) |
| `blocked_sites_at` | 지금 실제로 막아야 할 주소가 무엇인가 | 데몬 |

그룹을 하나도 안 고른 시간대는 첫 번째에서 참, 두 번째에서 빈 목록이다.

## 겹치는 시간대

데몬은 시간대 목록을 그대로 돌지 않는다. 매 초 `blocked_sites_at`이 그 시각에 켜진
시간대들의 그룹을 모아 주소 합집합을 만들고, 정렬해서 `hosts`에 쓴다. 정렬은 같은
내용일 때 `hosts` 파일이 흔들리지 않게 하려는 것이다.

화면에서 보이는 주간 막대(`WeekTimeline`)는 같은 계산을 요일 단위로 미리 한 것이다.
`merge.ts`가 자정을 넘는 구간을 다음 날로 쪼개고, 겹치거나 맞닿은 구간을 하나로 합친다.

## 스키마를 바꾸면 데몬을 다시 설치해야 한다

데몬은 앱과 따로 도는 별개의 바이너리다. `/Library/Application Support/Break/break-daemon`에
설치된 것은 앱을 새로 빌드해도 바뀌지 않는다. v1 데몬이 v2 파일을 읽으면 `sites`가 없어서
빈 목록으로 읽고, 에러 없이 "차단 해제"로 간다 — 아무것도 안 막는데 아무 데도 안 보인다.

그래서 `store::load_from`에 가드를 넣었다. 파일의 `version`이 그 프로그램이 아는 버전보다
크면 `StoreError::UnsupportedVersion`으로 거절한다. 데몬은 이걸 `RulesUnreadable`로 로그에
남기므로(`/Library/Logs/Break/daemon.log`) 다음부터는 조용히 지나가지 않는다.

거절해도 격리는 하지 않는다. 파일이 깨진 게 아니라 읽는 쪽이 낡은 것이기 때문이다.

앞으로 `RULES_VERSION`을 올릴 때는 데몬 재설치가 같이 필요하다.

## 어긋난 데몬은 화면에서 보인다

가드만으로는 부족했다. 로그는 `/Library/Logs/Break/daemon.log`에 남지만 아무도 안 본다.
그동안 앱은 초록 불을 켜 두고 있었다 — `status::current()`가 plist 존재 여부와
`launchctl print` 성공 여부만 봤기 때문이다. 둘 다 참인데 데몬은 아무것도 안 막고 있었다.

그래서 `installed_is_current()`를 넣었다. 설치된 `/Library/Application Support/Break/break-daemon`과
앱이 설치에 쓸 바이너리(`source_binary()`)의 바이트를 비교한다. 길이가 다르면 거기서 끝내고,
같으면 내용을 읽어 비교한다. 둘 중 하나를 못 읽으면 "같다"로 본다 — 판단이 안 서는데 경고를
띄우지는 않는다.

결과는 `AppState.daemonNeedsReinstall`로 나가고 화면 두 곳에 쓰인다.

- 오른쪽 위 상태 원: 초록(정상) / 주황(돌지만 앱과 다름) / 빨강(중단)
- 시간대 탭 위 배너: "차단 프로그램이 앱보다 오래됐습니다" + 다시 설치 버튼

앱을 새로 빌드하면 다음 실행에서 바로 뜬다.

## 브라우저는 hosts가 바뀌어도 한동안 그대로 접속된다

데몬이 `hosts`를 고치고 `dscacheutil -flushcache`까지 하지만, 브라우저는 OS와 별개로 자기
DNS 캐시와 열린 연결을 들고 있다. 이미 떠 있는 브라우저에서는 방금 막은 주소가 계속 열린다.

그래서 **지금 차단 구간에 해당하는 시간대를 추가했을 때만** 확인 창을 띄우고, 예를 고르면
열려 있는 브라우저를 닫는다. 낮에 밤 시간대를 등록할 때는 묻지 않는다 — 그때 브라우저를
닫아 봐야 정작 밤에는 아무 소용이 없기 때문이다.

종료는 `kill`이 아니라 AppleScript `quit`이다. 브라우저가 세션을 저장해서 다시 켤 때 탭이
복원된다. 3초 타임아웃을 걸어 두어 종료 확인 창을 띄우는 브라우저에 물리지 않는다.

### 브라우저 목록을 손으로 관리하지 않는다

처음에는 이름 목록을 박아 뒀다가 Aside를 빠뜨렸다. 목록을 채우는 방식은 다음 브라우저에서
또 같은 일이 난다.

지금은 실행 중인 프로세스에서 `.app` 번들을 뽑고, 그 번들의 `Info.plist`가 `CFBundleURLTypes`에
`http` / `https` 스킴을 선언하는지 본다. 브라우저는 전부 선언하고, 아닌 앱은 안 한다
(Obsidian은 `obsidian`만 선언한다). Safari, Chrome, Arc, Dia, Aside, Whale이 전부 잡힌다.

헬퍼 프로세스는 자기 헬퍼 번들로 해석되는데, 헬퍼 `Info.plist`에는 URL 스킴이 없어서 걸러진다.
Break 자신의 번들은 따로 제외한다.

과하게 잡힐 가능성은 확인 창이 막는다 — 닫을 앱 이름을 먼저 보여주고 사용자가 고른다.
